# OTDEL

Система агентского бюро. Первый блок превращает материалы партнёра в проверяемую продуктовую базу знаний: источники → извлечение → продуктолог → исследование → проверка → автоматическая публикация.

**Сейчас реализованы этапы 1A (приём материалов), 1B (чтение документов) и 1C (продуктолог).** Материал загружается, хранится и читается постранично: у каждой страницы есть явный исход, текст, области-первоисточники и таблицы. Из прочитанных страниц продуктолог собирает **черновик** знаний: продукты, характеристики с единицами и условиями, глоссарий, вопросы-ответы и пробелы — каждый факт с дословной цитатой и ссылкой на страницу оригинала. Исследование, проверка и публикация (1D–1F) ещё не реализованы, и интерфейс их не изображает.

Ключ модели (OpenRouter) пока не задан. Это состояние настройки, а не ошибка: без ключа обращений к модели не происходит вообще, интерфейс называет недостающие переменные, а знания не создаются и не выдумываются. Чтение материалов при этом работает как обычно. Подробности: [продуктолог, 1C](docs/knowledge-1c.md).

Распознавание (OCR) в систему не встроено: она вызывает локальные `tesseract`/`pdftoppm` через адаптеры. Если их нет, страницы без текстового слоя получают честный статус «нужно распознавание» с причиной — не «прочитано» и не «пусто». Подробности: [чтение документов, 1B](docs/extraction-1b.md).

## Запустить локальный пилот

Требуются Git, Docker, Rust 1.98.1 и Node.js 22+.

```sh
make dev-init     # случайные локальные учётные данные в .local/
make db-up        # PostgreSQL 17 + pgvector на 127.0.0.1:58432
make migrate && make bootstrap
make server       # API на 127.0.0.1:18480
make worker       # чтение документов + разбор знаний + восстановление (отдельный терминал)
make worker-probe # что доступно: OCR-движок, растеризатор и адаптер модели
```

Интерфейс: `cd apps/web && npm ci && npm run dev` → [127.0.0.1:15173](http://127.0.0.1:15173).
Подробности: [бэкенд 1A](docs/backend-1a.md), [чтение документов 1B](docs/extraction-1b.md), [продуктолог 1C](docs/knowledge-1c.md).

## Посмотреть макет и проверить репозиторий

```sh
make check
make preview
```

Макет открывается на [localhost:4173](http://127.0.0.1:4173). В нём можно переключать состояния, открывать источники, создавать временный черновик и выбирать имена файлов. Данные демонстрационные, живут только в памяти вкладки; настоящей загрузки и обработки нет.

`make preview` обслуживает каталог `design/` на localhost; если макет ещё не получен, команда объяснит причину. `make check` проверяет отслеживаемые файлы, JS/JSON и гигиену репозитория. Перед проверкой новых файлов их нужно добавить в индекс Git. Эта проверка не заменяет тесты будущего приложения или исчерпывающий поиск секретов.

## Разработка

[Репозиторий](https://github.com/lindwerg/otdel) · [задачи блока 1](https://github.com/lindwerg/otdel/milestone/1) · [правила разработки](docs/development.md) · [участие](CONTRIBUTING.md).

ASTRA определяет задачу и принимает результат; Claude реализует её в собственной ветке/worktree. Каждая задача проходит diff-review, соответствующие тесты и PR. `main` защищён обязательным `repository-check`, актуальной базой, разрешением обсуждений и запретом force-push/удаления.

Проверка стадии прототипа остановит PR с новым Cargo/package-манифестом: в этом же PR необходимо подключить реальные build/lint/test и заменить временный guard. Зелёный CI сегодня не означает, что Rust-приложение протестировано.

Реальные материалы BASIS, архивы компаний, письма, локальная карта исходников и ключи остаются вне публичного репозитория. `.env.example` содержит только примеры для будущих адаптеров. Для просмотра макета ключи не нужны.
