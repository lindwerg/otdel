# P0 — проверка подготовки проекта

Дата: 2026-09-13. Область: план, дизайн-прототип, репозиторий и процесс разработки. Это не приёмка реализации блока 1.

## Проверено

- План 1A–1F имеет зависимости и критерии приёмки. Финальный сценарий основан на двух PDF BASIS, а не на просмотре фиктивного статуса «готово».
- Палитра и Отто взяты из правильного проекта Otdel. SHA-256 всех семи PNG совпадает с оригиналами. Шрифт Manrope перенесён с OFL-лицензией.
- Реальные PDF, компаниям соответствующие XML/ZIP, .env и персональные локальные пути не включаются в публичные файлы. Локальная карта исходников остаётся в игнорируемом каталоге.
- Node-проверка проходит на подготовленных отслеживаемых файлах: JS/JSON-синтаксис, структура документации, конфликты, гигиена содержимого. Это ограниченная проверка, не исчерпывающий поиск секретов.
- Независимый code-review: устранены пропуск .local, молчаливый пропуск файлов при ошибке чтения/размере, обход проверки symlink в последующем JSON/JS-шаге, ложная готовность CI для будущих манифестов и противоречивое разрешение worker push.
- Проверяющий использовал in-memory негативные сценарии: .local, большой/нечитаемый текст, конфликт, NUL, app-манифесты и symlink. Для отвергнутых JSON-ссылок нет чтения, для JS-ссылок нет subprocess; сообщения синтаксиса не цитируют содержимое.
- Независимый JS-review: исправлены загрузка через создание нового партнёра, неверный источник, возврат фокуса, невидимый file input и обратная связь за модальным окном.

## Браузерная проверка

Проверялся localhost-макет через браузер Codex. Демонстрационные состояния не вызывают настоящую обработку документов или внешние API.

| Сценарий | Результат |
|---|---|
| BASIS, материалы и вкладки | Отображаются, переключение работает |
| Сценарии «пусто/обработка/частично/готово/ошибка» | Доступны через явный переключатель демонстрации |
| Загрузка текущему партнёру | Отдельный диалог, не форма создания |
| Escape из загрузки | Фокус возвращается на вызвавшую кнопку |
| Пустое имя нового партнёра | Видимое сообщение об обязательном поле |
| Новый черновик | Создаётся в памяти вкладки; ввод `<b>` отображается буквальным текстом |
| Доказательство факта BP21 | Открывается источник презентации, страница 5 |
| Недоступный источник | Не подставляется доказательство другого факта |
| Оригинал страницы в макете | Сообщение об отсутствии оригинала видно внутри диалога |
| Версии и автоматическая публикация | Демонстрация отделена от реальных данных |
| Ширины 360, 768, 1440 px | Выполнены проверки основных экранов; горизонтального переполнения не обнаружено |

Загрузка содержимого реальных файлов, реальное сохранение, OCR, RLS, ответы моделей, лимиты расходов, миграции, backup/restore и Rust-тесты ещё не реализованы. Проверка screen reader и полноценная UAT приложения предстоят на соответствующих этапах. Демо-сценарий пока общий для экранов и не является моделью изоляции данных.

## GitHub и работа исполнителей

- Публичный репозиторий `lindwerg/otdel`; milestone блока 1 и задачи P0, 1A–1F.
- Собственные ветки/worktree для Claude Design, Platform и QA; последовательная работа по этапам.
- `main`: PR, обязательный `repository-check`, актуальность относительно main, запрет force-push/удаления, закрытые замечания. Защита распространяется на администратора.
- Формальных одобрений второго GitHub-аккаунта требуется 0: владелец работает под одним аккаунтом. Содержательное ревью ASTRA остаётся обязательным по правилам проекта; это не аппаратно доказанная независимость ревьюера.
- CI проверен на GitHub Actions. Добавление Cargo/package-манифестов требует в том же PR заменить временную проверку стадии прототипа настоящими build/lint/test заданиями.
- `make preview` ограничен localhost и каталогом design, при отсутствии index.html останавливается с понятной причиной.

## Граница готовности

Подготовка позволяет открыть и обсудить макет, выдать первую задачу Claude и проверить её через PR/CI. Продуктовая реализация начинается с 1A. Переход к блоку 2 допускается после полного рабочего прогона и исправлений по обратной связи владельца.
