# OTDEL

Система агентского бюро. Первый блок превращает материалы партнёра в проверяемую продуктовую базу знаний: источники → извлечение → продуктолог → исследование → проверка → автоматическая публикация.

**Сейчас реализованы этапы 1A (приём материалов), 1B (чтение документов), 1C (продуктолог), 1D (исследователь), 1E (проверка, публикация и поиск) и 1F (обновления, история и выгрузка).** Материал загружается, хранится и читается постранично: у каждой страницы есть явный исход, текст, области-первоисточники и таблицы. Из прочитанных страниц продуктолог собирает **черновик** знаний: продукты, характеристики с единицами и условиями, глоссарий, вопросы-ответы и пробелы — каждый факт с дословной цитатой и ссылкой на страницу оригинала. Утверждённый владельцем отраслевой вопрос исследователь превращает в **ограниченную** внешнюю работу: считанные запросы, страницы только с объявленных хостов, бюджет с резервированием — и выводы, каждый с дословной цитатой, точным адресом и датой чтения.

Проверяющий перечитывает каждую цитату в сохранённом тексте источника **заново** и ставит статус: подтверждено источником, гипотеза, неизвестно, расхождение или устарело. То, что прошло правила готовности, замораживается в **неизменяемую версию** и публикуется автоматически; то, что не прошло, честно остаётся неопубликованным и называет причину. Искать и задавать вопросы можно только по опубликованной версии: ответ либо содержит цитаты, либо прямо говорит, что ответа нет и какой пробел мешает.

Новый материал партнёра запускает новый цикл **сам**: прочитан → разобран → проверен → опубликован, без кнопки между этапами. Прежняя версия при этом не меняется — она становится замещённой и остаётся читаемой по закреплённой ссылке, а сбой проверки не отнимает у партнёра то, что уже опубликовано. Карточка партнёра отвечает, что именно устарело и почему, называя документ и номер его чтения; сравнение версий показывает, какое значение изменилось и по какому источнику. Отзыв версии действует немедленно. Журнал событий дописывается и не переписывается — даже владельцем схемы базы. Подробности: [обновления и приёмка, 1F](docs/updates-1f.md), результаты приёмки: [UAT 1F](docs/uat-1f.md).

Расширение входов (DOCX/XLSX/PPTX, веб-ссылки, ссылка загрузки партнёру, почта и мессенджеры) не реализовано и нигде не изображается работающим.

Проверка и публикация не требуют ни одного ключа — правила детерминированы; обновления, история, сравнение версий, выгрузка и хранение тоже. Подробности: [проверка и публикация, 1E](docs/publication-1e.md).

Ключ модели (OpenRouter) пока не задан. Это состояние настройки, а не ошибка: без ключа обращений к модели не происходит вообще, интерфейс называет недостающие переменные, а знания не создаются и не выдумываются. Чтение материалов при этом работает как обычно. Подробности: [продуктолог, 1C](docs/knowledge-1c.md).

Поисковый провайдер тоже не выбран — и это решение владельца, а не умолчание системы. Пока не заданы endpoint, ключ **и список разрешённых хостов**, ни один внешний запрос не выполняется и бюджет не расходуется: адаптеры, собранные из неполной настройки, вообще не содержат HTTP-клиента. Произвольные ссылки не открываются никогда: читаются только объявленные хосты, переадресации не выполняются, `robots.txt` соблюдается. Подробности: [исследователь, 1D](docs/research-1d.md).

Семантическая половина поиска — тоже настройка, и её отсутствие ничего не ломает. Без провайдера embeddings **векторы не строятся вообще**: псевдовекторы не создаются, поиск идёт по точным значениям и полному тексту, а ответ прямо называет режим `keyword` и причину. Расширение `pgvector` ставится отдельной командой `make db-extensions`, потому что оно требует прав суперпользователя, которых у роли миграций намеренно нет.

Распознавание (OCR) в систему не встроено: она вызывает локальные `tesseract`/`pdftoppm` через адаптеры. Если их нет, страницы без текстового слоя получают честный статус «нужно распознавание» с причиной — не «прочитано» и не «пусто». Подробности: [чтение документов, 1B](docs/extraction-1b.md).

## Запустить локальный пилот

Требуются Git, Docker, Rust 1.98.1 и Node.js 22+.

```sh
make dev-init     # случайные локальные учётные данные в .local/
make db-up        # PostgreSQL 17 + pgvector на 127.0.0.1:58432
make migrate && make bootstrap
make server       # API на 127.0.0.1:18480
make worker       # чтение + разбор + исследование + проверка/публикация + восстановление и очистка истории (отдельный терминал)
make worker-probe # что доступно: OCR-движок, растеризатор, адаптер модели и адаптеры поиска
```

Интерфейс: `cd apps/web && npm ci && npm run dev` → [127.0.0.1:15173](http://127.0.0.1:15173).
Подробности: [бэкенд 1A](docs/backend-1a.md), [чтение документов 1B](docs/extraction-1b.md), [продуктолог 1C](docs/knowledge-1c.md), [исследователь 1D](docs/research-1d.md), [проверка и публикация 1E](docs/publication-1e.md), [обновления и приёмка 1F](docs/updates-1f.md).

## Посмотреть макет и проверить репозиторий

```sh
make check
make preview
```

Макет открывается на [localhost:4173](http://127.0.0.1:4173). В нём можно переключать состояния, открывать источники, создавать временный черновик и выбирать имена файлов. Данные демонстрационные, живут только в памяти вкладки; настоящей загрузки и обработки нет.

`make preview` обслуживает каталог `design/` на localhost; если макет ещё не получен, команда объяснит причину. `make check` проверяет отслеживаемые файлы, JS/JSON и гигиену репозитория. Перед проверкой новых файлов их нужно добавить в индекс Git. Эта проверка не заменяет тесты будущего приложения или исчерпывающий поиск секретов.

## Разработка

[Репозиторий](https://github.com/lindwerg/otdel) · [задачи блока 1](https://github.com/lindwerg/otdel/milestone/1) · [правила разработки](docs/development.md) · [участие](CONTRIBUTING.md).

ASTRA определяет задачу и принимает результат; Claude реализует её в собственной ветке/worktree. Каждая задача проходит diff-review, соответствующие тесты и PR. `main` защищён обязательным `repository-check`, актуальной базой, разрешением обсуждений и запретом force-push/удаления.

Проверка стадии прототипа остановит PR с новым Cargo/package-манифестом: в этом же PR необходимо подключить реальные build/lint/test и заменить временный guard. Зелёный CI сегодня не означает, что Rust-приложение протестировано.

Реальные материалы BASIS, архивы компаний, письма, локальная карта исходников и ключи остаются вне публичного репозитория. `.env.example` содержит только примеры для будущих адаптеров. Для просмотра макета ключи не нужны.
